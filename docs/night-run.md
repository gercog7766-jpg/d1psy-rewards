# NIGHT RUN

`/games/night-run` — свободная аркада без платы за вход и без проигрыша баланса. Три полосы, стрелки/A-D, кнопки и горизонтальные свайпы. Вертикальная прокрутка страницы и pinch zoom сохраняются. Присланный владельцем фиолетовый кот отображается вместо стрелки; прозрачный WebP (250×384, около 24 КБ) подготовлен без перерисовки персонажа. Упаковка — `scripts/build-night-run-character.py`, публичный версионированный ресурс `/games/night-run-cat-v1.webp`.

## Новые забеги (версия 2)

Фиксированная симуляция — 10 шагов в секунду. Скорость дороги растёт с 80 до 140 мировых единиц за шаг, прибавляя единицу каждые 2 секунды, затем остаётся ограниченной для играбельности. Меняется расстояние за шаг, а не ход серверного времени.

Монета появляется через независимый случайно распределённый интервал 300–450 шагов (30–45 секунд), затем планируется следующая. Интервал вычисляется детерминированно по серверному seed и индексу возможности подбора. Ускорение не сокращает этот таймер. Подбор начисляет **1 обычную монету** через `rewards_coin_transactions`; баланс отображается в инвентаре аккаунта. Это не отдельный скин. Пропущенная монета не оплачивается. Платы и ставок нет; один активный забег на пользователя. Новый забег доступен раз в 4 часа от начала предыдущего. Уже подтверждённые награды сохраняются после столкновения или остановки.

## Движение и коллизии

Мировые координаты полос — 0, 1000, 2000; персонаж перемещается к выбранной полосе не более чем на 500 единиц за шаг. Препятствия пересекают плоскость контакта через каждые 1000 единиц пути. Сервер вычисляет положение персонажа **в момент пересечения** плоскости внутри шага; проверка только конечной полосы не используется.

Поперечный размер препятствия — 0,64 ширины полосы, игровая зона ног персонажа — 0,32; суммарная половина ширины равна 480 мировым единицам. Точное касание границы безопасно. При столкновении дистанция и положение фиксируются непосредственно на контакте. Спрайт привязан нижней точкой к той же плоскости, где заканчивается передний край препятствия; плавное отображение использует реальные координаты, а не отстающую за полосой стрелку. Голова и уши не являются отдельной зоной столкновения.

Перед и после запланированной монеты освобождается участок в 700 мировых единиц, чтобы её нельзя было перекрыть препятствием. Положение монеты на дороге определяется расстоянием соответствующего будущего шага с учётом ускорения. Клиент и SQL используют одинаковые целочисленные формулы; проекция и размеры спрайтов отделены от расчёта награды.

## Совместимость и сохранение

Версия сохраняется в записи игры. Старые открытые клиенты продолжают запрашивать старый старт и получают версию 1; новая страница запрашивает версию 2. Общий RPC шага выбирает физику по сохранённой версии. Текущий старый забег не переинтерпретируется: его первоначальные правила (включая минутный интервал) действуют до завершения. Новые поля имеют безопасные значения по умолчанию; существующая история и монеты не пересчитываются.

Клиент отправляет пакеты выбранных полос (до 30 шагов), примерно каждые 2 секунды и немедленно при подборе/столкновении/остановке. Сервер не принимает клиентскую сумму, координаты монеты или итог столкновения. Шаги не могут опередить часы БД. Отсутствие подтверждения 8 секунд или отставание симуляции более 5 секунд завершает забег. HUD «Зачислено» показывает подтверждённые монеты. Потерянный ответ повторяется с прежним checkpoint; состояние согласуется без повторной оплаты.

Все изменяющие RPC сначала блокируют пользователя, затем игру. Прогресс и начисление фиксируются атомарно. Уникальная пара `(game_id, minute)` сохраняется; историческое имя столбца `minute` теперь означает порядковый номер возможности подбора (для версии 1 — минутный индекс). Повтор старого checkpoint возвращает сохранённое состояние. Таблицы закрыты RLS и REVOKE для браузерных ролей, RPC — `SECURITY INVOKER` с пустым search_path и доступом только service_role. HTTP проверяет сессию, Origin, JSON, допустимую версию старта, форму тела и лимит запросов.

Эти проверки защищают от ускоренных начислений, подмены награды и повторных выплат. Они не доказывают, что управление выполняет человек: бот может имитировать допустимый ввод в реальном времени.

## Проверено

- PGlite: SQL и клиентская физика совпадают на ускоряющихся забегах, интервалы независимы от скорости, выплаты однократны, старые и новые версии работают рядом, соседняя полоса и граничные контакты проверены.
- Проверены безопасные маршруты и доступность монет на 15 seed по четыре минуты, максимальная скорость и формула дистанции, потеря ответа после выплаты, откат записи при невозможности изменить кошелёк, сохранение наград после столкновения/таймаута, роли и блокировки.
- UI: выбранные кнопки управления, первая монета версии 2, повтор запроса, загрузка персонажа и привязка нижней точки к плоскости контакта. HTTP: авторизация, CSRF, версии старта, запрет клиентской награды, ресурс WebP и ссылка в «Играх».

Визуальный прогон на физических телефонах не выполнялся. Реальные production-награды при проверке не создавались. Версии миграций сохранены по истории БД после применения через MCP; локальный Supabase CLI ранее не запускался в этой среде. Юридические черновики другой задачи в релиз не включены.

## Leaderboard

Authenticated `/api/me/night-run/leaderboard` exposes only ten best completed runs, one per non-banned user. Distance descending, then elapsed ticks ascending, then oldest start/id break ties. Distance is integer metres: v2 world distance / 40, legacy tick × 2. Active runs appear only after eight seconds without a heartbeat (already expired under gameplay rules). Names use safe text nodes. No game IDs, seeds, user IDs or balances are exposed; RPC remains service-role only and does not write rewards. The table refreshes every 15 seconds on visible pages and after confirmed endings. Desktop puts it left of the field; mobile puts it after the game and controls.

Game catalog covers are supplied square artwork, shipped in 480/960 WebP sizes with full composition and immutable versioned URLs.

## Running presentation

Passed obstacle rows remain in the render window until their full geometry is below the canvas. Near objects render after the runner, far objects before it. Procedural alternating boots, body bob/lean and speed-scaled peripheral streaks follow world distance; reduced-motion preferences disable bob, lean and streaks. Physics, server replay, coin schedule and score units are unchanged.

## Four-hour start limit

New runs now share a server-enforced four-hour window from the previous start, across both game versions and all request IDs. Restoring an active run is allowed; ending or abandoning it does not reset the window. See `game-leaderboards.md` for timing and validation.
