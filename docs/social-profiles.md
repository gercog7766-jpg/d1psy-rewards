# Social profiles

Authenticated users can view another member's current main market goal (skin, variant, current price, and a floored 0–100% savings bar). The target's exact wallet balance is never returned. Private profiles hide both inventory and goal from other members; owners retain access.

`/community` contains incoming/outgoing friend requests, accepted friends and private conversations. Profiles provide request/accept/cancel/remove, message, gift and block actions. Messages are plain text, 1–2000 characters, rate limited to 20/minute per sender. Blocked users cannot initiate requests, messages or gifts. Threads return only the viewer/peer pair, with 50-message cursor pagination and recipient-only read markers. Inbox refreshes every 10 seconds while visible; drafts survive refresh and failed sends.

Gifts transfer existing coins, never create rewards. Each ordered sender/recipient pair has a cumulative limit of 10 coins per Moscow calendar day (00:00 reset), with positive integer amounts. Sender funds and recipient eligibility are checked in SQL. Both user rows are locked in UUID order, consistent with the existing wallet lock protocol. Debit, credit and gift receipt commit together. Request UUIDs deduplicate retries; reusing a UUID with another payload fails. Self gifts, insufficient funds, blocked, banned and restricted participants are rejected. Both ledger entries appear in wallet history.

All social tables have RLS and no anon/authenticated grants. RPCs are invoker functions with an empty search path and service-role-only execution. The Express layer derives the sender from the signed session, validates inputs and same-origin JSON writes, and marks personal responses no-store. Persistent device login covers `/community`. No real user transfers or messages are sent during validation.

Validation: `npm test` (40 tests), `npm run typecheck`, `npm run build`. Social DB tests use isolated PGlite fixtures; UI tests use JSDOM and HTTP tests use the real Express entry point with a mock backend. Tests cover privacy, friendship authorization, message isolation/read markers/pagination/rate limits, gift daily pairs, reset dates, atomic sum preservation, retries, blocked/self/restricted/insufficient-funds rejection and denied direct client access. Mobile styles use a single-column breakpoint at 650px; no real-device visual verification is claimed.
