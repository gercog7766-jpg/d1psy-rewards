# Referral program V2

Each signed-in user receives a stable random 24-hex invitation code. `/ref/:code` saves the first valid invitation for 30 days in an HttpOnly SameSite=Lax cookie. The existing single-use OAuth state carries that code through Twitch and consent. Binding runs only behind authenticated `/api/me` or `/api/me/referrals`, after persistent-device validation. It uses the server-resolved actor UUID, never client-supplied user identity. Links survive Twitch renames. One immutable parent per user; global bind lock prevents concurrent cycles; self/shared-Steam/cyclic links are rejected.

Qualification requires authenticated attribution, a valid trade URL, and 50 eligible coins earned after binding. Positive daily bonuses and Night Shift coin rewards are allowlisted by their trusted ledger type/reason. Item sales must reference the same user's sold win and actual amount, and prove origin: a giveaway round, streamer round award, Night Shift item or successful upgrade. Direct shop item resale is excluded regardless of value/volume. Gifts, manual credits, promo codes, game rewards, ordinary level rewards and contract-output sales do not qualify. Upgrade winnings count even if the input was bought: this is a completed risk-bearing upgrade, not direct resale.

One qualification event pays 15 personal coins; if the referrer is approved in production streamer profiles (or the enabled primary streamer), it pays 5. The server resolves this status at qualification, not at link creation. Streamer giveaway budgets are never read or written. Existing `signup_bonus_paid_at` prevents repeat bonus; in V2 it records enqueue time, while the events' `settled_at`/`settlement_id` prove processing. No historical reward/backfill is run.

Recurring events: 2% of internal item value on admin-confirmed sent/received delivery; 1% of the source skin's value on lost upgrades, excluding extra coin payments. Pending/cancelled orders and successful upgrades pay nothing. Contracts are outside the last accepted scope. Item value is captured in the order at request time; legacy pending orders without a value capture it on the next status update. Order and win delivery share a withdrawal source key to prevent double commissions across the two existing admin routes. Existing sales-based 2% and participation-based 20-coin rewards are removed.

All math uses integer hundredths and bigint; no floating point or rounding. An event worth 35 parts plus one worth 80 parts produces 1 coin and retains 15 parts. A worker settles every 5 seconds (30 referrers / 5000 events per referrer per batch). Wallet row locks serialize workers. Ledger insert, remainder update and event settlement are atomic. Failure leaves events pending, so retries cannot duplicate money or lose fractions. Payouts run separately from gameplay transactions to avoid cross-user gameplay/balance lock cycles. No settlement endpoint exists in the browser. Banned referrers are not paid by the worker.

Private tables have RLS and no client-role grants; functions are invoker and service-role only. The authenticated endpoint paginates 20 invitees and exposes only own stats, nicknames, progress/trade-ready flag and recent own earnings. It never exposes Steam URLs, Twitch IDs, other users' wallets or streamer budgets. Coin history and notifications label the new `referral_reward` type.

Validation: PostgreSQL-compatible integration tests cover complete qualification, whitelist exclusions, both bonus rates, payout remainder across multiple referrals/events, snapshots, duplicate confirmation, failed settlement rollback/retry, attribution cycles, bans, grants and stable codes. HTTP integration uses mocked Twitch upstream to exercise real consent, single-use state restoration, persistent login, binding and actor isolation. No fabricated production sessions or reward transactions are used for verification. A real human Twitch/browser acceptance check remains useful after deployment.
