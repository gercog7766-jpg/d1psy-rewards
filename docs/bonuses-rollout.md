# Страница «Бонусы»

Страница `/bonuses` объединяет прежние промокоды, семидневную серию, случайный бонус раз в 24 часа и разовый бонус за Telegram. Пункт меню «Промокод» заменён на «Бонусы». Семидневный блок перенесён из личного кабинета.

## Награды

При каждом получении сервер выбирает одну категорию равновероятно среди доступных игроку. Категории: 100 XP, 1–7 монет, один оплаченный вход в «Три двери» за 10 или 20 монет, скин для апгрейда стоимостью до 10 монет, ещё не купленная обычная рамка, 150 SP текущего NIGHT SHIFT и один ключ текущей недели THE VAULT. SP доступны до завершения сезона S1. Ключ доступен в открытом недельном событии в пределах существующего лимита. Скин выбирается из доступного каталога; полученная копия предназначена для апгрейдера. Рамка остаётся навсегда. Бонусы не требуют пополнения.

Бонус дня отсчитывает 24 часа с момента выдачи, независимо от семидневной серии с обновлением в полночь Москвы. Сервер блокирует пользователя при выдаче, сохраняет результат и идентификатор запроса в одной транзакции с наградой. Повтор запроса возвращает ту же награду. Ошибка начисления откатывает весь запрос.

## Установка базы до публикации приложения

На VPS применяется **только** `supabase/migrations/20261118130000_bonus_center.sql`. Автообновление приложения миграции не применяет. Сохраните SQL из конкретного проверенного коммита и выполните:

```bash
docker exec -i dropso-db-local sh -c \
 'export PGPASSWORD="$POSTGRES_PASSWORD"; exec psql -X -U supabase_admin -d dropso_live -v ON_ERROR_STOP=1 --single-transaction -f -' < /root/bonus-center.sql
```

После успешного выполнения можно объединить PR в main. Дождитесь автоматического обновления, сверьте `/health` с SHA публикации. На `/bonuses` проверьте промокод, семидневную серию и выдачу случайного бонуса. Повторный запрос не должен создавать новую награду.

## Telegram

Проверка подписки требует бота Telegram. Создайте бота через @BotFather и добавьте его администратором канала @dropso_cs2. Для проверки `getChatMember` административный доступ бота необходим; публикация постов для работы этой функции не нужна.

Приложение читает три переменные:

- `BONUS_TELEGRAM_BOT_TOKEN`: токен бота, вводится на VPS; не публикуйте его в чате или репозитории.
- `BONUS_TELEGRAM_BOT_USERNAME`: имя бота без @.
- `BONUS_TELEGRAM_WEBHOOK_SECRET`: случайная строка не короче 32 символов, например 32 случайных байта в hex.

Сохраните значения в закрытом root-owned файле окружения, подключите его отдельным `EnvironmentFile=` в dropso.service и перезапустите сервис. Для этого бота зарегистрируйте webhook через Telegram Bot API `setWebhook` с параметрами:

```json
{"url":"https://dropso.site/api/bonuses/telegram/webhook","secret_token":"ЗНАЧЕНИЕ_BONUS_TELEGRAM_WEBHOOK_SECRET","allowed_updates":["message"]}
```

Бот должен быть выделен для этой интеграции: регистрация заменяет прежний webhook данного бота. Проверьте `getWebhookInfo` и отсутствие ошибок доставки.

Игрок открывает канал, нажимает «Привязать Telegram», переходит по персональной ссылке к боту и нажимает «Запустить». Затем возвращается на сайт и нажимает «Проверить и забрать 10 монет». Ссылка действует 15 минут. Telegram ID берётся из проверенного webhook, а членство — из `getChatMember`. В базе действует уникальность пользователя и Telegram ID: один Telegram не позволяет получить награду на нескольких аккаунтах. Начисление и чек выдачи атомарны.

Без настройки бота остальная страница работает, а блок Telegram сообщает, что проверка настраивается.

## Проверки

`tests/bonuses.test.mjs` проверяет выдачу каждого типа, повторы, 24 часа, отдельные аккаунты, конкурирующие клики, откат при ошибке, лимит ключей, запреты браузерным ролям, Telegram-привязку, одноразовое начисление, проверку членства, CSRF и безопасное отображение текста в окне награды. Полный деплойный набор запускается через `node scripts/deploy/checks.mjs`.
