# Контракты: инвентарь → один скин

`/contracts` использует авторизацию сайта. Десять слотов (3–10 предметов), поиск и реальные изображения инвентаря. Удалены демо-плашка, бумажный контракт, учебная коллекция и правая панель вероятностей.

GET `/api/me/contracts` постранично загружает только собственные `awaiting_choice` выигрыши с положительной стоимостью и доступным статусом доставки. Подтверждение предупреждает о безвозвратном списании и возможности получить более дешёвый предмет.

POST принимает только UUID запроса и 3–10 разных UUID предметов. Пользователь определяется сервером по подписанной сессии. RPC `rewards_run_contract` доступен только service_role, работает как security invoker. Блокировка пользователя и упорядоченные блокировки предметов сериализуют обмен с продажей, получением и апгрейдом. Вся операция выполняется одной транзакцией. Повтор того же запроса возвращает прежний результат. Тот же UUID с другим набором отклоняется.

Расчёт сохраняет демонстрационное распределение целевого процента: 30–80 (55%), 81–105 (25%), 106–150 (15%), 151–200 (5%). Процент внутри диапазона выбирается равномерно на сервере. Из доступных вариантов каталога выбирается ближайший к целевой стоимости вариант в пределах 30–200% суммы. **Эти доли относятся к целевому проценту, а не гарантированным диапазонам цены результата:** цены каталога дискретные. Если варианта нет, операция отклоняется без списания. Варианты с нулевым остатком исключаются; каталог служит справочником награды, как в апгрейдере, остаток магазина не списывается.

Входные предметы получают `choice_status=contracted`, остаются в истории с подписью «В КОНТРАКТЕ» и не могут продаваться/использоваться повторно. Результат создаётся как отдельный disabled prize вне пула розыгрышей, затем как обычный доступный `rewards_wins` с `source_type=contract`, износом и видом варианта. Его можно продать или запросить к выдаче обычными действиями инвентаря. Монеты напрямую не начисляются и не списываются. `round_id=null`: текущие триггеры не начисляют XP за победу и прогресс розыгрыша/покупки.

Клиент сохраняет UUID незавершённого запроса в sessionStorage, повторяет сетевой сбой с тем же ключом и блокирует выбор во время обмена. Результат и цены определяет исключительно база данных. История обменов хранится в закрытой `rewards_contracts`.

Проверки: UI с мокированным API, полный Express с авторизацией/валидацией/CSRF, SQL-тест реального PostgreSQL-движка PGlite (дубликаты, чужие/устаревшие предметы, повтор, откат после ошибки, права, отсутствие изменений кошелька). PGlite сериализует запросы: это не нагрузочный тест нескольких PostgreSQL-сессий.
