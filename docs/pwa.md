# D1PSY Rewards PWA

## Пользовательский сценарий

Manifest `/manifest.webmanifest`, иконки PNG (192/512/maskable/apple), старт `/app`, standalone. В аккаунте блок установки, инструкции для Android/iPhone, включение/отключение уведомлений и проверочный push. Разрешение запрашивается только после нажатия. На iPhone/iPad нужен iOS/iPadOS 16.4+ и запуск с иконки на главном экране. Установка и разрешения ОС требуют действий владельца устройства.

Push: только личный выигрыш из стримового розыгрыша (`round_id IS NOT NULL`, `source_type IS NULL`). Все устройства аккаунта с активной подпиской получают уведомление. Покупки, апгрейды и контракты не уведомляют. Нажатие открывает инвентарь через `/app`. Тестовый push доступен самому пользователю раз в минуту; реальные награды не создаются.

## Вход

После первого входа случайный 256-битный device token находится в HttpOnly/Secure/SameSite=Lax cookie. В БД хранится SHA-256 токена, а не его значение. Срок 180 дней без активности, продление при использовании не чаще раза в сутки, предельный срок устройства 365 дней. Сеанс проверяется сервером; блокировка пользователя, истечение или удаление записи запрещают восстановление. Существующие действующие 7-дневные сессии автоматически переходят при открытии аккаунта, `/app` или `/api/me`.

Для совместимости существующих обработчиков подписанная `rewards_session` генерируется внутри запроса после проверки device token. Она помечена deviceSession; без действительного устройства использовать её нельзя. Существующий OAuth state и referral flow сохранены; принудительное force_verify убрано. Выход удаляет серверную сессию устройства, каскадом удаляет его подписки и очищает cookies. Другие устройства остаются в аккаунте.

Повторный вход возможен после явного выхода, удаления cookies/данных приложения, смены устройства, блокировки или истечения срока. В iOS браузер и установленная PWA могут иметь разные хранилища: первый вход в установленном приложении иногда нужен отдельно. Пароль Twitch не сохраняется.

## Доставка без Render

Триггер складывает новые выигрыши в приватную очередь в одной транзакции с выигрышем. pg_net вызывает Supabase Edge Function `drop-push` после commit. pg_cron раз в минуту повторяет вызов только при готовых заданиях. Поэтому остановка/сон web-сервиса Render не останавливает push-доставку уже созданных дропов. Сам механизм определения победителя по-прежнему зависит от существующего giveaway engine.

Edge Function проверяет отдельный секрет webhook, берёт задания через SKIP LOCKED и 3-минутную аренду, шифрует Web Push стандартной библиотекой, отправляет по 5 параллельно (до 20 за вызов). Ошибки 404/410 удаляют подписку; временные ошибки повторяются до 6 попыток, срок уведомления 24 часа. После сетевой неопределённости возможна повторная доставка; одинаковый notification tag объединяет дубли на устройстве. Устаревшие задания и просроченные устройства очищаются ежедневно.

VAPID private key и секрет вызова хранятся в Supabase Vault. В исходниках ключей нет. `rewards_push_credentials` SECURITY DEFINER оправдан только чтением Vault и доступен исключительно service_role. Trigger-функции находятся в неэкспонируемой схеме rewards_private. Таблицы закрыты RLS и GRANT; публичным ролям права не выдаются. API берёт пользователя из сессии. Endpoints ограничены известными push-провайдерами, перенаправления при доставке запрещены. JSON и Origin/Sec-Fetch-Site проверяются для изменения подписок. Данные сторонних подписчиков не возвращаются.

## Кеш и обновления

Service worker хранит только общие иконки и страницу отсутствия сети. Аккаунт, HTML с личными данными, баланс, API, выигрыши, игровые действия и авторизация не кешируются. OAuth и logout обходят обработчик fetch. При offline вместо личных данных показывается нейтральная страница. Код PWA и worker отдаются с no-cache, автоматической перезагрузки текущей игры нет.

## Развёртывание

1. Две миграции `pwa_push_and_sessions`, `push_delivery_dispatch`.
2. Один раз сгенерировать VAPID и секрет webhook, сохранить private/dispatch в Vault и заполнить `rewards_push_config` ссылками на secrets. Повторно не менять ключи без плана переподписки устройств.
3. Deploy `supabase/functions/drop-push` с verify_jwt=false: собственная аутентификация x-push-dispatch-key обязательна. Запросы без секрета получают 401. SUPABASE_SERVICE_ROLE_KEY предоставляется Edge runtime; новые Render env vars не нужны.
4. Опубликовать сервер. Проверить manifest, worker, PNG, метаданные и приватность API.

## Проверки

PGlite: сроки/блокировки сессии, владение подпиской, отсутствие дублей, фильтр только дропов, аренды и повторные попытки, права анонимных ролей, отзыв при logout. Полный Express: metadata, восстановление по одной device cookie, отклонение подписанной сессии без устройства, отзыв и CSRF. Worker: только общие кеши, API/OAuth bypass, offline fallback, безопасный путь клика. UI/JSDOM: разрешение по нажатию, подписка/отписка, тест и инструкции. Edge worker: успешная отправка, 410, 503. Production: закрытый dispatcher 401, авторизованный пустой dispatch 200, cron и ограничения ролей. Финальная проверка появления системного уведомления на реальном телефоне требует установки и пользовательского разрешения; в окружении не проводилась. Скриншотная браузерная проверка не проводилась.

Примечание advisory: pg_net помечается как extension_in_public по метаданным расширения. Проверено, что все его функции/таблицы находятся в отдельной схеме net, публичных объектов расширения нет; установленная версия extrelocatable=false. RLS без клиентских policies на новых таблицах намеренна: доступ только service_role.
