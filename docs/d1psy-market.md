# D1PSY MARKET: первые три этапа

Обновляется существующий `/shop`: избранные варианты, главная цель и умные фильтры. Ссылка «Мои желания» в профиле ведёт на `/shop?view=favorites`; вкладка избранного остаётся внутри магазина.

## Избранное и цель

Сердечко сохраняет вариант по ID (конкретный износ и normal/StatTrak/souvenir), а не только название скина. В обычном каталоге под именем показывается вариант, к которому относится сердечко. В модальном окне действия относятся к текущему типу и износу. Во вкладке желаний несколько вариантов одного скина отображаются отдельными строками. Для предметов без вариантов сохраняется ID самого предмета.

Одна главная цель на пользователя. Выбор цели автоматически добавляет этот вариант в избранное. Удаление цели не удаляет желание; удаление самого желания снимает соответствующую цель. Цена, изображение, название и наличие читаются из текущего каталога, баланс — из полного журнала монет. Нет резервирования или списания монет. Недоступные варианты сохраняются в желаниях и явно помечаются; покупка из них отключена.

До 500 избранных вариантов на аккаунт. Существующее старое избранное сохранено: для целого скина выбран доступный normal FT, если он есть, иначе другой доступный вариант; предметы без вариантов остаются фиксированными. Старая таблица не изменяется и не удаляется. Старый магазин на странице аккаунта скрыт существующим кодом; новый вход в желания находится рядом с заголовком инвентаря.

## Фильтры

- «Могу купить»: доступный вариант с положительной ценой не выше текущего баланса.
- «Почти накопил»: доступный вариант дороже баланса, при этом накоплено не меньше 80% цены (не хватает до 20% включительно).
- «Мои желания»: только конкретные сохранённые варианты, включая временно недоступные.
- Износ, тип, цена, поиск и редкость работают совместно. Условия качества/типа/цены проверяются на одном и том же варианте. Строка и открываемое окно показывают этот вариант.
- Сортировка по отображаемой цене по возрастанию/убыванию; неизвестные цены в конце. Без фильтров сохраняется привычный normal FT, если доступен.

Данные перечитываются после покупки, при возвращении во вкладку и каждые 30 секунд (когда окно выбора закрыто). Обновление каталога в открытом модальном окне сохраняет выбранный тип/износ и обновляет цену. Подтверждение покупки, корзина, количество и серверные проверки покупки используют существующий код.

## Хранение и доступ

Новые таблицы `rewards_market_favorites` и `rewards_market_goals` защищены RLS и доступны только service_role. Составной FK не позволяет сделать целью чужое желание. API `/api/me/market` берёт пользователя из подписанной Twitch-сессии; пользовательские ID из тела запроса не используются. PostgreSQL-функции `rewards_market_state`/`rewards_market_set` возвращают только собственные записи. Изменения одного пользователя сериализуются advisory-блокировкой. Повторное добавление того же варианта не создаёт дубликат.

Публикация: применить `supabase/migrations/20261106002813_market_favorites_goals.sql`, затем обычный deploy Render. Новых env vars нет.

Проверки: `npm test`, `npm run typecheck`, `npm run build`. SQL/PGlite: перенос прежних желаний, точные варианты, одна цель, владение, актуальные цены и наличие, каскадное удаление, отсутствие записей в журнале монет, баланс с более чем 1000 операциями и права ролей. Полное приложение + JSDOM: API-авторизация, качество/тип/бюджет, доступный BS вместо дорогого FT, избранное и цель после перезагрузки, обновление цены/баланса, недоступные варианты, сортировка и существующая корзина/покупка конкретного варианта. Скриншотная проверка в локальном Chromium недоступна в этой среде.
